# UI/UX Reference Study

Inspect supplied pages with a browser when available. Capture the full composition and a useful detail, noting viewport, date, URL and state in a research record. If only a screenshot is available, limit claims to visible evidence. Do not infer hover, motion, keyboard behavior or responsiveness from a still image.

## Extract structure
Record a small matrix: surface/job, composition, type hierarchy, spacing rhythm, navigation, controls, state communication, and evidence. Distinguish marketing shell from embedded product UI. Inspect actual product content rather than deriving an app solely from its homepage.

Look for these transferable relationships: quiet navigation against strong content; narrow task rail against flexible workspace; restrained color against purposeful status; consistent grid against varied media; small technical labels against regular-weight headings. Treat these as candidate patterns, not a mandatory aesthetic.

Translate evidence into rules with a reason and a boundary. Example: “Use a narrow grouped task list beside the active conversation to retain work context; collapse it into a drawer when the conversation would become unreadable.” Avoid “make it look like the source.”

## Deliver
Produce 5–8 rules, a list of elements not to carry over, and a mapping from each rule to the target product's jobs. Mark observations, recommendations and project preferences separately. Preserve provenance in a private research appendix if the user asks for brand-neutral deliverables. Omit source names from the delivered design vocabulary in that case; do not erase provenance or pretend the recommendations are measured observations.

Do not copy logos, source wording, distinctive illustrations or proprietary fonts. Recreate relationships using original content and available typefaces. Validate with a target-product example and an opposite-theme example before promoting a pattern to a reusable rule.
